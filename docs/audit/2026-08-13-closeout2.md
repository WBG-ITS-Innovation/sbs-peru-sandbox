## 0. Environment caveats, stated up front

Two facts about the machine this ran on, because they qualify every result
below.

### 0.1 `uv` is not installed on this host

The README lists `uv` as a prerequisite, and the shipped scripts invoke
`uv run`. It is absent here — not on `PATH`, not in a login shell, not
anywhere on the filesystem:

```
$ zsh -lc 'which uv; uv --version'
uv not found
zsh:1: command not found: uv
```

The project venv at `.venv/` is intact and complete (alembic, pytest, openai,
httpx, asyncpg, arq, fastapi all import). Interestingly `uv`'s managed Python
is still present — tracebacks below resolve through
`~/.local/share/uv/python/cpython-3.12.13-macos-aarch64-none/` — so the binary
appears to have been removed while its data directory survived.

Rather than edit the shipped scripts (which would invalidate "run as
shipped"), a shim was placed on `PATH` for this session only, in the
scratchpad, mapping `uv run <cmd>` to `.venv/bin/<cmd>`:

```sh
case "$1" in
  run) shift; ...; exec "$VENV/bin/$cmd" "$@" ;;
```

**What this means for the results.** Every script ran byte-unmodified and every
assertion below is real. But real `uv run` also performs a dependency sync
against `uv.lock` before executing, and the shim does not. So these runs prove
the code works against the venv as it currently stands; they do not prove the
venv matches `uv.lock`. Anyone reproducing this should install `uv` first, and
should treat a lockfile-drift failure as unexplored territory rather than a
regression.

### 0.2 The stack was warm and was deliberately cooled

Before starting, `:3000` (cockpit dev server), `:8443` and `:8000` (two API
processes) were live, alongside compose postgres/redis/keycloak/worker/
webhook-listener. The two API processes had started at 12:10, i.e. **before**
the base commit landed at 15:15, so they were running pre-healthcheck code. All
three were stopped and restarted from cold for the walk in §1.3.

### X.2 — field count: 27, being 23 base + 4 conditional bancaseguros

**Ruling.** Per Res. SBS N° 04036-2022 Anexo 1-A the granular schema is 23 base

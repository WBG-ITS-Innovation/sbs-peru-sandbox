# P11 demo-ui-polish — walkthrough

## Summary

Five targeted UI enhancements that close the gap between "API works"
and "supervisor experience feels real". Demo is tomorrow with the
two-laptop setup; these polish items are what the regulator will see
first.

No layout redesigns, no new routes, no changes to persona switcher /
i18n bundles / auth flow. `agent_run` schema is additive only.

## What landed

### Enhancement 1 — Taxonomy harmonization panel on Findings

New component `app/src/components/findings/TaxonomyPanel.tsx`,
slotted after the Resolution status sub-panel on
`/findings/[id]`. Renders one row per `(field, original_value,
canonical_value, dictionary_version)` tuple read from
`agent_run.final_output.taxonomy_normalizations` via a new
`_extract_taxonomy_normalizations` helper in
`api/sbs_api/findings/builder.py`.

* Collapsed by default — title shows the count, a "Show / Hide"
  toggle reveals the table.
* Hidden entirely when the complaint has no normalizations (empty
  list → panel does not render).
* ES + EN labels via i18n keys `findings.panels.taxonomy_*`.

### Enhancement 2 — Resolution status sub-panel

The five Annex 1-A resolution-side fields landed by p11-demo-ready
now have a dedicated `Estado de la resolución` Card (i18n key
`findings.panels.resolution_section`). Old behaviour: scattered
under the complaint header. New behaviour:

* `estado_reclamo`, `tipo_resolucion`, `fecha_resolucion`,
  `monto_pendiente` in a 4-column grid.
* `descripcion_resolucion` (redacted text) full-width inside the
  same card.
* Each `Field` renders only when its value is non-null. The whole
  sub-panel is hidden if every field is null.

### Enhancement 3 — Cockpit taxonomy harmonization counter

New endpoint `GET /v1/internal/cockpit/taxonomy-stats` (registered in
`api/sbs_api/routes/cockpit.py`, response model
`TaxonomyStatsResponse`). Same shared-secret auth as the existing
internal cockpit route.

* `normalizations_today` — count of `taxonomy-normalized` audit rows
  with `created_at >= 00:00 UTC today`.
* `institutions_affected` — distinct count of
  `complaints.institution_id` joined on the audit row's
  `object_id`.
* `as_of` — ISO 8601 timestamp the tile renders.

UI: new `TaxonomyStatsTile` component placed alongside the filter
toolbar above the tier panels. ES + EN strings under
`cockpit.taxonomy.tile_*`.

### Enhancement 4 — Tier badge color differentiation

* `Badge` gains `tier1` and `tier2` variants reading from
  `--color-brand-cyan` (#009FDA, WBG palette) and
  `--color-brand-gold` (#F5BD24).
* `TierPanel` header pill now uses `<Badge variant={tier_variant}>`
  with the wider `Tier 1 NRT` / `Tier 2 Batch` labels.
* Findings detail header swaps the generic "source" pill for the
  same tier-variant Badge driven by `complaint.source ==
  'api_realtime'` → `tier1`, otherwise `tier2`.
* Builder change in `cockpit/builder.py`: each tier panel emits a
  `tier_variant` field so older snapshots without it fall back to
  `tier1` on the UI side.

### Enhancement 5 — Unknown-taxonomy visual flag

* New column `complaints.flag_unknown_taxonomy` (migration
  `20260527_0001`, nullable=false, server default false, indexed).
  The orchestrator now writes this from
  `taxonomy_outcome.flag_unknown_taxonomy`.
* The cockpit SSE delta + initial snapshot carry
  `flag_unknown_taxonomy` plus an `unknown_terms` list (first three
  unrecognised surface forms) and `unknown_terms_total`. The audit
  rows are queried in one shot per tier panel; cost is bounded by
  `RECENT_LIMIT`.
* `ComplaintCard` renders a 3 px yellow left border, a soft-gold
  "Unknown term" pill next to the complaint id, and a native
  tooltip listing the first three `field: "value"` lines (with
  trailing `…` when there are more).
* New `Badge` variant `warning` for the pill (soft gold to draw the
  eye without being a severity claim).
* New filter checkbox above the tier panels: "Show only
  unknown-taxonomy rows". Drives a local boolean in
  `CockpitClient`; `TierPanel` filters `recent` by
  `flag_unknown_taxonomy === true` when the flag is set.

## Known limitations

* The unknown-term tooltip uses the browser's native `title`
  attribute. Screen readers expose it; mouse users see it after the
  ~1 s hover delay. Trade-off: zero JS, no library, no a11y
  regression risk for the demo. A richer in-app tooltip can land
  later without changing the data path.
* `flag_unknown_taxonomy` is set only on rows ingested after the
  `20260527_0001` migration. Pre-existing rows backfilled to
  `false` and will not show the yellow border or pill even if their
  source surface forms were unknown. The audit chain still carries
  the ground-truth `taxonomy-unknown-term` rows for those
  submissions.
* The taxonomy-stats counter resets at 00:00 UTC, not Lima local.
  Acceptable for a same-day demo; a deployed cockpit should swap
  the window to America/Lima before audiences cross midnight.

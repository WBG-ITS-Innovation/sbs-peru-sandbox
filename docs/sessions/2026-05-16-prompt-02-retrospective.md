# Prompt 2 retrospective — supply chain & secrets

## What was the bet

Prompt 2 set out to land the supply-chain and secrets substrate (scanners, dependency-update tooling, environment-variable policy, security disclosure path) and close four carry-over items from Prompt 1 (two `close_prompt.py` bugs, a label bootstrap, a Zscaler doc). The bet was that locking these decisions and their tooling early — in Part 1, before the application stack arrives in Part 3 — produces a cleaner inheritance for every later Part, instead of a Part 9 retrofit. The risk being hedged was the well-known one: pre-pilot codebases that defer security plumbing tend to either ship with weak posture and get caught at audit time, or eat a costly six-week retrofit just before handoff. The implicit second bet was that the cost of writing five ADRs and a 50-line research subsection now is smaller than the cost of explaining "we'll get to it" in front of an SBS reviewer.

## What landed vs. what was planned

Material divergences from the original Prompt 2 spec (referenced against commit `138c2bb` on `main`, plus the post-merge follow-ups `11aafa4` and `2657432`):

- **Section 11 of `market-comparators.md` was split out to `docs/research/supply-chain-precedents.md`.** The spec didn't call for a separate file — the supply-chain content was originally appended to the regulator-domain comparator doc. The maintainer flagged the dilution; the split, the `benchmark-checker` rule widening, and the citation updates across five ADRs were done before closeout.
- **`benchmark-checker` subagent rule widened** from "must cite `market-comparators.md`" to "must cite a research file under `docs/research/`." Direct consequence of the split. Same change had to land in `CLAUDE.md` (principle 6), `docs/adr/README.md`, `docs/research/README.md`, and `.claude/commands/benchmark-check.md`. A class of bug — hardcoded filenames in the rule's enforcement layer — that didn't surface until the file count went from one to two.
- **`--no-cross-review` flag removed entirely** rather than kept as a back-compat alias. Spec was ambiguous on the interaction with the new `--skip-cross-review-with-reason`. The strict-single-path bypass is more auditable.
- **`requirements-dev.txt` at repo root became an addendum block in `scripts/requirements-harness.txt`.** Avoids the naming collision with Part 3's `pyproject.toml` + `uv.lock`.
- **`.github/workflows/dependency-review.yml` removed in the same PR's follow-up commit.** First CI run failed: `dependency-review-action@v4` requires GitHub Advanced Security, not licensed for `WBG-ITS-Innovation`. Coverage deferred to Part 9 via `pip-audit` + `npm audit`. ADR 0019 amended; tracked at [#8](https://github.com/WBG-ITS-Innovation/sbs-peru-sandbox/issues/8). The threshold decision (`high`-and-above blocking) remains locked; only the implementation moved.
- **`.github/workflows/secret-scan.yml` rewritten in the same follow-up commit.** First CI run failed: `gitleaks-action@v2` requires a commercial license for organisation-owned repos. The gitleaks binary is free; the wrapper isn't. Workflow now downloads a pinned binary directly. ADR 0016 amended; tracked at [#9](https://github.com/WBG-ITS-Innovation/sbs-peru-sandbox/issues/9). Same scanner, same cadence, same redaction.

## What the harness revealed about itself

**Where the harness helped, concretely.** The carry-over fix mechanic worked: Prompt 1's two `close_prompt.py` bugs (silent cross-review failure tolerance, deploy-test regex false-positive) were both closed in Prompt 2 with regression tests, and the act of writing those tests caught a *third* bug — the heredoc-indent recurrence. The pytest run failed against the "fixed" `write_session_journal`, surfaced eight-space leading whitespace, and forced the actual fix (explicit `"\n".join(parts)` instead of `textwrap.dedent` against an embedded `chr(10).join(...)`). The verbal claim "I rebuilt the heredoc" had been false; the test caught the rebuild's incompleteness in under a second. That's the test layer earning its keep against the LLM-claim-vs-reality gap that the rest of this harness is built to address.

The `benchmark-checker` subagent run against all five ADRs surfaced a real defect on ADR 0016 (Divergence #2 was framed as a divergence from precedent when, per the cited research section, it was *alignment* with the common pattern — the wrapper-vs-binary minority is the actual divergence). That's the kind of slip a self-review almost never catches. The cross-review then surfaced eight additional substantive items on the same ADR, three of which would have been merge-time blockers if the rule were stricter. Two independent reviews catching different defects on the same artifact is the design pattern working — neither alone would have been enough.

**Where it slowed things down.** The cross-review file naming (`{date}-staged-diff.md`) is not stable across multiple runs in the same day; the closeout overwrote the verification-round review. The audit trail survives via git history, but a vendor browsing `docs/reviews/` sees only the last review per day. The closeout pipeline assumes a TTY for the typed approval gate, so an LLM session can't complete the pipeline end-to-end — that's a feature, not a bug, but it means the handoff point between LLM and operator is the typed approval, not the merge. The session journal's subagent-verdict table stayed empty: the closeout script writes a placeholder ("_See inline reports during /close-prompt run._") and the table is never auto-populated. The cross-review-finding triage line stays as a TODO unless the operator fills it manually; nothing in the pipeline blocks merge if it isn't.

**Where the seams will tear under load.** The "WBG org configuration assumption" pattern is a class of bug, not a one-off. Both broken CI workflows assumed an org-level capability (GHAS, paid Action license) that the org doesn't have. Any future workflow that depends on `secrets.GITLEAKS_LICENSE`, GHAS-gated Actions, org-level app installations, or repository rulesets will fail the same way on first run. There is no pre-flight check for "does this PR require capabilities the org doesn't have." The cross-review-finding triage process is informal: Prompt 2's cross-review surfaced eight items; one was auto-addressed (the Divergence #2 reframing), one was out of scope (branch protection), two went into Part 9 issues, and four sit in the journal's "Notes" without a tracked disposition. Two prompts in, that's manageable. Twenty prompts in, it won't be — undecided cross-review findings will accumulate into a quiet backlog that nobody reads.

## Implications for Prompt 3 and beyond

- **Pre-flight org-capability check becomes an explicit step.** Before writing any `.github/workflows/*.yml`, any `gh api` call, or any code that references `secrets.<X>`, the prompt's plan must answer: "Does this depend on org-level configuration (GHAS, paid Action license, org secret, app installation, ruleset, branded label set)?" If yes, the plan lists exactly what it depends on and verifies presence before merging. Add this to the `/part-start` skill's output as a checklist line. The pattern is now ADR-eligible: a future ADR ("Org-capability dependencies must be declared in the prompt spec") would formalise it.
- **Prompt 3 is the first prompt where the application stack actually exists.** That means `pyproject.toml` and `uv.lock` will be the first real manifests in this repo. The `pip` ecosystem entry in `.github/dependabot.yml` has been pointing at an empty `/` directory; the grouping config (minor + patch) has never fired. Once Prompt 3 lands, the next Dependabot PR will be the first live test of the grouping. Watch the first one — if grouping fails for any reason (wrong ecosystem, wrong directory, lockfile format), fix in Prompt 3's follow-up, not later.
- **Cross-review filename stability.** Either (a) include a content hash or commit-SHA in the cross-review filename so re-runs don't overwrite, or (b) accept overwriting and remove the per-day file from `docs/reviews/` once a successor exists. Doing nothing means `docs/reviews/` becomes lossy. Recommend (a); it costs eight characters in the filename and preserves the audit trail in a browseable form.
- **Open the triage line before typed approval, not after.** The closeout script should refuse to commit if the cross-review's `## Triage` section still contains the `_TODO: human-filled_` literal. That's a one-line check in `close_prompt.py` and a regression test against the same pattern; add it in Prompt 3 alongside the pyproject work.
- **Populate the subagent verdict table from the closeout, not from the operator.** The closeout script knows whether each subagent was invoked and what verdict it returned (or could know, if the operator records it). Today the journal's subagent-verdict table is template text that gets carried over into every closeout. Either auto-fill from a structured input file the operator writes during the pipeline, or remove the table — but stop shipping empty tables as if they were filled. Decide in Prompt 3.
